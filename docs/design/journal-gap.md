# Journal gap

A loss is shared audio or screen material that will not reach the journal. While an unseen loss was found in the last 7 local calendar days, and nothing more urgent is happening, the pill, the status view, on this device, and the widgets say there is a gap and which day. The day line uses the capture day. The symbol is `calendar.badge.minus`. The widget field is `journalGap`. A missing field is no gap.

Looking at the status content marks the losses then on screen. That look is one visit: it starts when the content is visible and the scene is active, and it ends when the content hides or the scene leaves active. A rotation, a size-class change, or a split-view resize does not end it while that content is still showing, and the losses it displayed stay displayed. When the change hides the content and nothing carries it, the visit ends, so the next showing is a new visit. Collapsing to the phone presents the status sheet only when the visit is showing a loss. Losses that appear during the visit stay on screen and unmarked until the next visit. Nothing is marked while the scene is not active. An empty surface marks nothing. Marking happens after the notice is read again; if the content stopped showing, or a newer request or the scene leaving active superseded that read, it marks nothing. Needs attention outranks the gap on every widget, including the circular one.

Events live in `AppGroup/JournalEvents`: one file per loss, one file per diagnostic or imported row, and one file per seen mark. The broadcast extension and the app use the same directory. A chunk under 0.1 seconds is a diagnostic. A file whose size cannot be read stays on disk and is not an event. A store failure does not stop capture: the new material is written under a fresh name. Every kept or numbered part (`screen.mp4.part`, `screen-audio.m4a.part`, and their siblings) stays until a later pass records it and then deletes it. A directory is not removed while one of those parts is still unrecorded, except by the owner's own removal. Replacing an existing final records that file when it existed and is not an identical copy. When the existing final cannot be recorded or measured, both files stay where they are and screen recording goes on to the next window: the old final is delivered, and the window kept beside it is recorded as a loss after delivery.

When the phone made no audio for a window (phone audio was not used, or it ended with nothing to deliver), the broadcast's own audio is delivered as the segment's audio, and the segment's length comes from the window, not from a discarded phone clip. A phone audio file that failed to finalize is resolved first; if it turns out to be missing, the broadcast's audio is delivered instead.

A delivered segment is never sent again. A leftover directory of a delivered segment is retired on a later pass, and until then it is not counted as waiting or listed as failed. One segment that cannot be retired yet does not hold up the others.

Removing something on this phone, or removing a segment's screen content, is recorded as the owner's removal, a diagnostic and never a loss, and it removes everything the owner asked to remove, kept parts included, even when the event store cannot be written.

Imported interruption files are dated at import for retention and keep the record's own time in the diagnostics export. They are seen. Importing them again does not count them twice. Each record is written on its own, so other writes are not held up by the import. The source files stay. Nothing under the Caches root is deleted.

The last journal identity is `journal-identity.json`. It is the instance id and the normalized CA fingerprint, not the phone's client certificate, so pairing the same journal again marks nothing. Unpairing does not erase it. The same journal, an unknown identity, or a missing file marks nothing. A different known journal marks every event seen. A mark-all that fails is tried again on the next launch.

Diagnostics keep a collapsed row until 30 days after its last occurrence. A seen mark leaves only when its event file is confirmed absent, and only on a resume or reconcile. A mark stays when that file cannot be read, or when the losses or diagnostics directory is missing or cannot be listed. Losses still expire from the day they were found. Unseen losses inside the notice window stay.
